# UI/UX-принципи «Кошика з акцій» (обов'язково перед будь-якою зміною інтерфейсу)

Сучасна мобільна практика (Apple HIG з Liquid Glass, Material 3 Expressive, NN/g), зведена до правил для цього продукту.
Мета кожного екрана — **одна головна дія за один дотик**, без читання.

## 1. Простота й мінімум тексту
- Заголовок = питання або назва (2–4 слова). Без пояснень під заголовком; якщо без пояснення не зрозуміло — міняй дизайн, а не дописуй текст.
- Підписи до кнопок — дієслово + об'єкт: «Додати в кошик», «Що приготувати». Не «Натисніть, щоб…».
- Підказка — максимум одне коротке речення, і лише там, де без неї помиляються.
- Числа замість слів: «3 продукти · фарш — завтра», а не «У вас є 3 продукти, один з яких скоро зіпсується».
- Одна думка — один рядок. Якщо блок має > 25 слів — скорочуй.

## 2. Один екран — одна головна дія
- Одна основна кнопка (темна/зелена) на екран, решта — другорядні (світлі) або посилання.
- Головна дія — у зоні великого пальця (нижня половина екрана), повна ширина, ≥ 48 px заввишки.
- Прогресивне розкриття: рідкісні налаштування ховаємо в нижній аркуш (bottom sheet) або «Ще», а не показуємо всім.

## 3. Менше кроків
- Розумні значення за замовчуванням (люди, час, магазин, дати) — питаємо лише те, чого не можемо вгадати.
- Зберігати одразу (autosave) замість кнопки «Зберегти»; дати «Скасувати/Повернути» замість «Ви впевнені?».
- Оптимістичний інтерфейс: показуємо результат одразу, синхронізуємо у фоні; помилку — тостом з «Спробувати ще».
- Не просити реєстрацію чи дозволи наперед: спершу цінність, потім прохання (геолокація, push, «Сільпо» — після пояснення в 1 рядок).

## 4. Звичні патерни (не вигадувати)
- Навігація: нижня панель ≤ 4–5 вкладок; «←» у шапці; свайп назад працює.
- Редагування елемента: торкнувся рядка → нижній аркуш з діями (а не кнопки в кожному рядку).
- Списки: найважливіше зверху (терміновість, акція), групи з короткими заголовками.
- Порожній стан: що тут буде + одна кнопка «Додати…», без абзаців.
- Завантаження: скелетони замість спінерів; > 1 с — показати, що відбувається.

## 5. Візуальна ієрархія
- Шкала шрифтів 13/14/16/18/24/32; на екрані ≤ 3 розміри.
- Колір означає стан: червоний — терміново/помилка, золото — акція, зелений — головна дія/успіх. Не фарбувати для краси.
- Кольорові бейджі статусу (завтра / 5 днів / 3 тижні) замість речень.
- Відступи 8/12/16/24; картки з радіусом `--r-lg`; не більше 2 рівнів вкладених карток.
- Прозорі/«скляні» поверхні — лише під контролами; текст завжди на суцільному фоні (контраст ≥ 4,5).

## 6. Доступність (не обговорюється)
- Зони дотику ≥ 44×44 px (Apple) / 48 dp (Android).
- Контраст тексту ≥ 4,5:1; не передавати сенс лише кольором — додай слово чи іконку.
- `aria-label` для іконок-кнопок, `aria-live` для статусів, фокус видно.
- Поважати `prefers-reduced-motion` і темну тему.

## 7. Рух і відгук
- Кожен дотик дає відгук ≤ 100 мс (стан натиснення, вібрація `haptic`).
- Анімації 150–250 мс, лише щоб показати, звідки що взялося (з'явився рядок, закрився аркуш).
- Тости — коротко, з дією («Прибрано · Повернути»).

## 8. Як працювати (процес)
1. Перед великою зміною — 2–4 варіанти знімками (iPhone 13) і питання власнику.
2. Після зміни — знімок до/після, перевірка тексту (скоротити ще раз) і агент `ux-reviewer`.
3. Метрики в PostHog: якщо після спрощення кроки воронки не ростуть — переглянути.

## Чек-лист перед комітом UI
- [ ] Одна головна дія, у нижній половині, ≥ 48 px
- [ ] Немає пояснювального абзацу; кожен текст ≤ 1 рядок
- [ ] Збереження без окремої кнопки (або чому потрібна кнопка)
- [ ] Порожній стан і стан завантаження продумані
- [ ] Зони дотику ≥ 44 px, контраст ≥ 4,5, темна тема
- [ ] Знімок на iPhone 13 переглянуто очима

Джерела: Apple Human Interface Guidelines (developer.apple.com/design/human-interface-guidelines), Material 3 (m3.material.io), Nielsen Norman Group (nngroup.com), WCAG 2.2.
